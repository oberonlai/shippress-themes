### Look-alike clusters (from the screenshots)
- **Cluster A, the "washi split" (worst):** yuzu-chaya, shiro-horitsu, seiji-utsuwa, kami-no-ne, and to a lesser extent ikebana-kyoshitsu and fuji-shinkyu. They share a pale ivory base, a serif headline with an italic second voice on the left and a photo on the right, a row of three stats, then a "Four ___" grid. Almost every one also uses H1 + F2.
- **Cluster B, full-bleed misty photo + ivory:** hinoki-yado and mori-no-kai (green, serif, photo hero, stat row).
- **Overall:** 14 of 17 themes use H1 (logo left, nav right), and 12 use F2 (multi-column sitemap). Six themes sit on a washi-ivory + sumi base.

## 2. Taxonomy

### Header patterns
H1 logo-left / nav-right bar · H2 centred logo with nav split left and right · H3 vertical side rail (fixed left) · H4 hamburger only + full-screen overlay menu · H5 magazine masthead (huge wordmark with a dateline row) · H6 index tabs / ruled cells · H7 bottom-docked bar (nav at the viewport bottom) · H8 transparent over hero, turning solid on scroll · H9 two-tier (utility strip + main nav) · H10 floating pill nav · H11 vertical Japanese-type nav on the right edge · H12 split: logo top-left, nav as a numbered list in the hero corner

### Footer patterns
F1 giant wordmark · F2 multi-column sitemap · F3 one-line minimal · F4 newsletter-led block · F5 marquee / ticker · F6 map + address card · F7 big-CTA band (booking/visit) · F8 photo-strip footer · F9 colophon / credits page style · F10 split two-tone panel · F11 hours and calendar table · F12 stamped seal + vertical text column

### Home layout archetypes
L1 full-bleed photo hero · L2 split screen · L3 editorial masthead + index list · L4 horizontal scroll · L5 vertical type · L6 bento grid · L7 single-column long-read · L8 card mosaic / masonry · L9 oversized typography only · L10 map / locator first · L11 product-first grid · L12 timeline / chaptered scroll · L13 sticky media with scrolling text · L14 tabbed / filter-first directory

### Palette rule
Each theme gets one dominant hue family plus a lightness (light, mid or dark). Adjacent themes never share a family. A washi-ivory + sumi base is allowed for at most one theme in any run of three; prefer white, grey, tinted or dark grounds.

### Font pairings (all OFL)
Syne + Inter · Space Grotesk + IBM Plex Sans · Zen Maru Gothic + Nunito · Klee One + Noto Sans JP · Bricolage Grotesque + Figtree · DM Serif Display + DM Sans · Libre Caslon + Karla · Darker Grotesque + Work Sans · Gloock + Public Sans · Young Serif + Outfit · Anton + Lato · Sora + Inter · Literata + Mulish · Zen Old Mincho + Zen Kaku Gothic · Rubik Mono One + Rubik · Gowun Batang + Lexend · Fraunces (avoid; used) · Cormorant/EB Garamond/Hanken (avoid; overused)

## 4. Rules for the theme routine
1. At the start of a round, take the first `todo` row, set it to `claimed (YYYY-MM-DD)`, and commit that change.
2. Follow its industry, type, palette, fonts, header, footer and layout exactly. Record H/F/L codes in meta.json as `header`, `footer` and `layout`.
3. At the end, set the row to `done (<commit>, YYYY-MM-DD)` and add the theme to the section 1 inventory.
4. Any deviation (a font swap, a palette tweak) must be noted in the row and must not break the no-adjacent-repeat rule.
5. When every batch-1 row is done, plan the next 20 (batch 2) with the same no-repeat rules checked against all existing themes, then continue. Repeat for each later batch.
